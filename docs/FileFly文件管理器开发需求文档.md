## 1. 背景与目标

### 1.1 背景
NanoFile 已正式公测并上架微软应用商店，主打「现代化 Windows 11 原生体验 + 文件标签 + 全盘秒搜 + 全格式预览 + 本地加密保险箱」。这说明市场验证了一条明确的产品路径：**在系统自带文件浏览器不够用的地方，用轻量、快速、现代的体验切入**。

### 1.2 产品目标
做一款**跨平台（优先 Windows，其次 macOS）、轻量、极速、可标签化**的现代文件管理器：
- **吸收**各竞品的优点（速度、标签、预览、双栏、批量重命名等）；
- **规避**各竞品的缺点（卡顿、臃肿、价格高、学习成本高、功能残缺等）。

### 2.3 NanoFile 的初步短板（从公开信息推断，需规避）
- 仅 Windows 平台（macOS/Linux 缺失或刚起步），跨平台一致性未知；
- 免费公测期的商业模式与长期维护不确定；
- 标签依赖 NTFS ADS，**非 NTFS 分区/U 盘/exFAT 上标签会失效**（需要数据库兜底方案）；
- 无多标签页/双栏等重度用户能力的公开证据；
- 生态与开放性（插件、脚本、开源社区）未知。

## 3. 竞品分析

### 3.1 Windows 资源管理器（系统自带）

**优点**
- 系统级集成：右键菜单、Shell 扩展、网络位置、回收站、权限体系完整；
- 与任务栏、开始菜单、搜索、OneDrive 深度联动；
- 零学习成本，所有 Windows 用户都会用。

**缺点**
- 大目录加载慢、缩略图生成慢， frequently 未响应/卡顿；
- 无文件标签系统；搜索慢（非索引路径尤甚）、结果过滤能力弱；
- 多标签页（Win11 才加入）功能浅，无双栏、无高级排序/筛选；
- 预览能力弱（需开启预览窗格，格式支持有限）；
- 界面更新缓慢，信息密度低，批量操作繁琐。

### 3.2 macOS 访达 Finder（系统自带）

**优点**
- QuickLook（空格预览）体验极佳，是行业标杆；
- 标签（Tags）系统原生支持，可与 Spotlight 联动过滤；
- 与 macOS 桌面美学、iCloud、AirDrop/接力无缝集成；
- 列表/分栏/画廊视图，分栏视图导航高效。

**缺点**
- 无路径地址栏输入直达（需快捷键唤出「前往文件夹」，对新手隐蔽）；
- 无剪切（Cut）文件操作，Windows 用户常困扰；
- 窗口管理弱：无标签页时代遗留的多窗口混乱问题改善有限；
- 搜索（Spotlight）虽快但结果定位、语法过滤不够直观；
- 大量文件滚动时偶发卡顿；高级批量重命名、双栏对比均缺失。

### 3.3 主流第三方文件管理器

| 产品 | 平台 | 优点 | 缺点 |
|------|------|------|------|
| **Directory Opus** | Windows | 功能天花板：双栏、多标签、定制化极强、FTP/压缩包如文件夹 | 价格高（免费版受限）、学习曲线陡、界面偏传统、启动偏重 |
| **Total Commander** | Windows | 老牌稳定、双栏、批量重命名、插件生态庞大、体积小 | 界面 90 年代风格、键鼠操作门槛高、预览与现代化体验弱 |
| **XYplorer** | Windows | 便携免安装、脚本自动化、标签页+色标标注、搜索极强 | 收费、单窗口为主、界面信息密度过大对新手不友好 |
| **Files App** | Windows | Win11 Fluent 设计标杆、开源、云盘集成好、现代 UI | 性能一般（大目录偏慢）、功能深度不及 Opus/TC |
| **OneCommander** | Windows | 现代双栏、列式导航、预览好 | 免费版有限制、小团队更新节奏不稳 |
| **Q-Dir** | Windows | 多窗格免费轻量 | 界面老旧、无标签/预览体系 |
| **ForkLift** | macOS | 双栏、FTP/SFTP、同步、批量重命名 | 收费、非 Finder 替代定位（偏传输工具） |
| **Commander One** | macOS | 双栏、云盘/网络协议支持广 | 收费 Pro 版才完整、性能一般 |
| **Path Finder** | macOS | Finder 增强（双栏、权限、压缩） | 收贵、更新慢、偶有系统兼容问题 |

### 3.4 优缺点总结（提炼为设计原则）

**必须吸收的优点（众家之长）**
1. QuickLook 式空格预览 + 全格式（图/码/音/视/Office/EXIF）——NanoFile、Finder；
2. 全盘索引搜索 + 拼音匹配 + 语法过滤（如 `size:>100MB`）——NanoFile、Everything、XYplorer；
3. 文件标签系统，且**不丢**（NTFS ADS + 数据库双写）——NanoFile、Finder、XYplorer 色标；
4. 双栏 + 多标签页——Total Commander、Opus、ForkLift；
5. 智能首页（分类聚合、磁盘概览、云盘入口）——NanoFile；
6. 现代化 UI（Win11 Fluent / macOS 质感、深浅色、毛玻璃）——Files、NanoFile；
7. 批量重命名、压缩包免解压浏览——TC、Opus；
8. 键盘优先操作（方向键、快捷键体系）+ 命令面板（类 Raycast/VS Code）。

**必须规避的缺点**
1. 卡顿与未响应——架构上必须异步 IO + 虚拟化列表 + 缩略图异步管线；
2. 臃肿/启动慢——轻量安装包、冷启动 < 1.5s；
3. 高价与付费墙——核心功能免费，增值可选；
4. 学习成本陡峭——默认单栏简洁模式，双栏/高级功能渐进式露出；
5. 标签随文件系统/分区失效——双写策略（NTFS ADS + 本地索引库）；
6. 界面老旧/信息过载——现代设计系统 + 可调信息密度；
7. 预览/搜索残缺——预览与搜索作为 P0 一等公民。

## 4. 产品定位

> **一句话定位**：一款「快如闪电、好看、带标签和保险箱」的跨平台现代文件管理器——Windows 上是「资源管理器的完全体」，macOS 上是「Finder 的增强层」。

- 目标用户：重度文件使用者（开发者、设计师、办公族、资料控）；
- 差异化：**速度（毫秒级搜索/预览）+ 标签不丢 + 本地隐私保险箱 + 现代双栏多标签**；
- 商业模式：核心免费（口碑获客），Pro 解锁（云盘深度集成、同步、团队标签库）。

## 6. 非功能需求

| 维度 | 指标 |
|------|------|
| 性能-启动 | 冷启动 ≤ 1.5s（对标「轻快」，规避 Opus/TC 的重） |
| 性能-浏览 | 10 万项目录滚动 60fps；缩略图首屏 ≤ 500ms |
| 性能-搜索 | 百万文件索引查询 ≤ 100ms；增量索引延迟 ≤ 1s |
| 性能-预览 | 图片/代码预览打开 ≤ 300ms；视频起播 ≤ 1s |
| 稳定性 | 大目录操作绝不阻塞 UI 线程（全异步架构），崩溃率 < 0.1% |
| 安全 | 保险箱 AES-256；密码 PBKDF2/Argon2 派生；不采集文件内容，隐私本地化 |
| 兼容 | Win10 21H2+ / Win11；macOS 13+；长路径、Unicode/emoji 文件名 |
| 安装体积 | 安装包 ≤ 80MB（规避臃肿） |
| 可用性 | 默认模式零学习成本；高级模式有引导；快捷键可自定义 |

## 7. 技术选型建议

| 层 | 建议 | 理由 |
|----|------|------|
| UI 框架 | Windows: WinUI 3 / WPF+Fluent；macOS: SwiftUI+AppKit 混合；或统一 Tauri v2（Rust+WebView）+ 原生增强 | 现代 UI + 可控性能；Tauri 利于跨平台一致 |
| 核心引擎 | Rust（文件枚举、索引、缩略图、预览管线） | 毫秒级性能与内存安全的最佳平衡 |
| 搜索索引 | 自研 SQLite FTS5 + NTFS USN Journal / FSEvents 增量 | 百万级文件毫秒查询，避免 Everything 闭源依赖 |
| 标签存储 | NTFS ADS + SQLite 双写，冲突合并策略 | 吸收 NanoFile 的 ADS 优点并修复其跨分区失效短板 |
| 预览 | 图片: GPU 纹理直传（wgpu/D3D）；代码: Tree-sitter + Shiki；音视频: ffmpeg/系统硬解（Media Foundation/VideoToolbox） | 毫秒级渲染与全格式覆盖 |
| 加密 | age/AES-256-GCM + Argon2id | 现代密码学实践，避免自造加密轮子 |

## 9. 应用名称与仓库名称推荐

### 9.1 首选：**FileFly**（仓库：`filefly`）

**理由**：
- **Fly = 快 + 轻**：直接命中产品第一卖点（毫秒级搜索/预览、轻量不臃肿），暗合「让文件飞起来」；
- **语义直白**：File + Fly 组合一眼即懂是文件工具，全球用户无需解释，发音顺口、无歧义；
- **可品牌化**：可衍生口号「Let your files fly. / 让文件飞」；图标可用「纸飞机 + 文件夹」造型，与 NanoFile 的云朵文件夹形成差异化记忆点；
- **仓库友好**：`filefly` 全小写无连字符，npm/crates.io/GitHub 冲突概率低，衍生包可命名 `filefly-core`、`filefly-preview`、`filefly-index`。

### 9.2 备选
| 名称 | 仓库 | 理由 |
|------|------|------|
| **Swiftpan** / **Zippy File** | `swiftpan` | 强调极速；但 Zippy 易联想压缩格式，易混淆 |
| **TagNest** | `tagnest` | 突出标签差异化（标签之巢）；缺点是弱化了速度卖点，且对无标签需求用户吸引力窄 |
| **Lumo Files** | `lumo-files` | Lumen（光）+ 轻，现代感强、适合 macOS 调性；缺点是中文语境无直接含义，传播成本略高 |

**结论**：主推 **FileFly（`filefly`）**，备选 TagNest（若产品战略以「标签管理」为绝对核心）。

---

## 10. 风险与待确认项

1. **NTFS ADS 之外的文件系统**（exFAT/网络盘）标签一致性——需双写与合并策略的详细设计；
2. **微软商店审核与签名证书成本**；macOS 公证（Notarization）流程；
3. **音视频无损解码的授权**（如 APE/FMAC）需法务确认；
4. **云盘占位符文件**（OneDrive files-on-demand / iCloud braced files）的读写兼容性需专项验证；
5. NanoFile 后续迭代方向未知，建议每季度复核一次竞品功能矩阵。
