
## 0.1.15：修复侧栏"最近使用"恒为 0 项
- 根因：fs_record_recent 命令从未注册进 lib.rs invoke_handler，openEntry 每次打开的记录调用全部 "command not found" 静默失败 → recent_items 表恒 0 行（实测确认）
- 首页有数据是假象：来自 fs_home_stats 的兜底（按 mtime 扫描），掩盖了记录表空的问题
- 修复：①注册 fs_record_recent；②系统性比对前端 invoke 全部命令名 vs 注册表，发现 tag_apply_archive（标签智能归档）同样漏注册，一并补上；③openEntry 记录调用加 catch 防御，目录记为 location 类型（SpecialView isDir 判断依赖）
- 注意：历史记录无法追补（不会导入 Windows Recent），装新版后从新打开的文件开始积累
- 校验脚本：grep invoke 命令名 vs lib.rs 注册表 diff（今后回归可用）
- 产物：FileFly_0.1.15_x64-setup.exe (3.53 MiB) / .msi (4.89 MiB)

## 文件夹大小功能（0.1.20）
- 需求：详情/列表视图显示文件夹占用；性能敏感 → 设置开关（设置→外观→"文件夹大小"，ff-folder-size，默认开）。
- 后端 fs_dir_sizes：spawn_blocking + 8 线程并发 + 单文件夹 8s deadline/15万条目 cap + 5 分钟 TTL 缓存（OnceLock<Mutex<HashMap>>）；跳过符号链接；partial 标记前端显示 "≥"。compute_dir_size 迭代栈遍历；3 个单测（递归累计/空目录/超时 partial）。
- 前端：FileList 仅在 showsSizeCol（details 或 list 非紧凑）才请求；DIR_SIZE_MEMO 会话缓存 + INFLIGHT 去重；分批 64/次；未就绪显示 "…"；关闭开关完全不请求。
- fmtSize 规则改为用户要求：<1MB→KB、<1GB→MB、≥1GB→GB（<10 保留 1 位小数）、0→"—"、超大→TB。全局生效（含文件大小显示）。
