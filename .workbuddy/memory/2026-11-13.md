## Tab 间相互影响修复（0.1.24，keep-alive 架构）
- 根因：App.tsx 只渲染激活 tab 的视图，切 tab = 旧视图整个 unmount，搜索结果/扫描进度/列表状态全销毁。
- 方案：每个 tab 常驻一个视图实例（tabs.map 包 display:flex/none 的容器），切换只改可见性。BrowserPane 加 tabId/active props：tabId 绑定自己的 tab（navigateTab/backTab/forwardTab 定向导航），键盘处理 guard active 防止隐藏面板重复响应全局选区操作；双栏右栏仅激活 tab 显示（保持原逻辑）。
- 效果：后台 tab 搜索继续（SearchResults 常驻）、空间扫描继续（SpaceView 常驻，进度隐藏更新）、目录列表保持滚动与数据；注意隐藏面板的 2.5s 轮询与 ff-refresh 刷新会按 tab 数量叠加（可接受）。

## 页面不撑满窗口修复（0.1.26）
- 根因：0.1.24 keep-alive 的 tab 容器用 display:flex（行方向），flex 子元素按内容宽度收缩不拉伸 → HomePage 等内容型页面被压成内容宽度，右侧大片空白。
- 修复：容器改 display:block/none（块级子元素自动占满宽度）；BrowserPane 分支内部自带 flex 行容器（flex:1,minWidth:0）作为块级子元素宽度 auto 占满，双栏不受影响。
- 教训：keep-alive 可见性切换容器不要用 flex 做行内布局，除非给子视图显式 width:100%/flex:1。

## 文件列表无法滚动修复（0.1.27）
- 根因：0.1.26 把 tab 容器改回块级后，目录浏览分支的内层 flex 行容器没显式高度 → height:auto 由内容决定 → BrowserPane/FileList 的 height:100% 解析失效，列表容器无限撑高、外层不滚动（文件多时下面的看不到）。
- 修复：内层容器加 height:"100%"（tab 容器本身有确定高度，百分比可解析）。教训：块级 keep-alive 容器内所有需要撑满的中间层都要显式 height:100%，flex:1 只在 flex 父级下有效。

## 回收站加载超时修复（0.1.28）
- 根因：trash::list 串行探测 A..Z 盘符 Path::exists()，断连/慢速网络映射盘每次阻塞 5~10s（SMB 超时），累计超前端 30s 看门狗 → "加载超时"。用户机器配置了网络位置，命中此场景。
- 修复：fs/mod.rs 新增 drive_letters()（GetLogicalDrivesW 位掩码，只读系统状态不碰网络，永不阻塞；注意函数名无 W 后缀变体）；trash::list 改为按真实盘符并行枚举（thread+mpsc，JoinHandle drop 即分离）+ 15s 总预算超时返回部分结果；fs_drives 同步改用 drive_letters()（首页磁盘条同隐患）。
- 24 项测试全过（新增 drive_letters 测试）。
